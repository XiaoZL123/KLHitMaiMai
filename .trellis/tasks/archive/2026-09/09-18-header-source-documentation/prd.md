# 头文件说明与实现同步维护规范

## Goal

建立 STM32 模块头文件与对应源文件的可追踪说明习惯，使开发者和 AI 能从 `.h` 快速了解模块职责、公开接口及其作用，并避免接口说明与实现脱节。

## Background

- 工程模块采用同名 `.h/.c` 配对，例如 `Core/Inc/x42s_motor.h` 与 `Core/Src/x42s_motor.c`。
- 当前 STM32 代码风格已要求新增功能函数添加简短中文注释，但尚未明确头文件需要记录对应源文件用途和函数清单。
- 该任务只建立后续开发规范，不追溯改写所有既有模块文件。

## Requirements

- 在 `.trellis/spec/stm32/code-style.md` 中增加“头文件与源文件同步说明”规范。
- 规范要求每个项目自维护 `.h` 文件包含：对应 `.c` 文件用途、公开函数清单及每个函数的作用。
- 规范要求新增、删除、重命名函数或改变参数/行为时，同步更新 `.h` 的说明、声明和对应 `.c` 实现。
- 规范要求函数注释使用简洁中文；实现细节仍留在 `.c`，不在头文件暴露私有状态或私有函数。
- 规范明确第三方 HAL/CMSIS 头文件不做批量改写；已有业务头文件只在后续修改该模块时按新规范补齐。
- 保留工作区中用户已有的业务代码修改，不修改 `SoftWare/BIGDICK/Core/Src/main.c` 或其他业务文件。

## Acceptance Criteria

- [x] `stm32/code-style.md` 明确记录 `.h/.c` 配对说明、函数清单和同步更新规则。
- [x] 规范包含一个符合当前 C11/STM32 风格的 `.h` 注释示例。
- [x] 规范明确公开接口与私有实现的边界，以及 HAL/CMSIS 文件的排除范围。
- [x] PRD、规范文件通过路径和内容检查，工作区用户已有 `main.c` 修改未被覆盖。

## Out of Scope

- 不为本任务批量重写现有 `.h/.c` 文件。
- 不改变任何 CAN、OPS、OLED 或底盘控制行为。
- 不修改 CubeMX 生成文件、HAL/CMSIS 第三方文件或用户未授权的硬件资料。

## Open Questions

- 无。该任务是已确定的轻量级编码规范更新，可使用 PRD-only 规划。
