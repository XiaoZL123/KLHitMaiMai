# 底盘运动解算与定点移动

## Goal

实现四轮麦克纳姆（全向）底盘的运动学解算，并为后续基于 OPS 位姿反馈的定点移动建立可同步发送四个 X42S 电机指令的控制边界。

## Confirmed Facts

- 主控为 STM32H743VIT6，使用 `FDCAN1` 与四个 X42S 电机通信。
- 电机地址与轮位已确认：地址 1 为左前轮，地址 2 为右前轮，地址 4 为左后轮，地址 3 为右后轮；X 固件驱动已提供速度、位置、停止和 `X42S_SyncStart()` 接口。
- 麦克纳姆轮直径暂定为 `100 mm`；左右轮中心距与前后轮中心距暂按 `1:1`，即等距矩形底盘处理，实际中心距数值后续再标定。
- 位置指令长度为 17 字节，需要拆成 3 个经典 CAN 帧；当前 FDCAN TX FIFO 为 8 个元素，发送函数在 FIFO 满时最多等待 5 ms。
- 当前 `main.c` 仍属于用户工作区修改，本任务不得覆盖或擅自恢复该文件中的现有改动。
- 工程中存在麦克纳姆轮模型资料，但代码中尚未固化轮径、轮距、轴距、电机安装方向和编码器比例参数。

## Requirements

- 建立独立的底盘运动控制模块，输入底盘期望速度或目标位移，输出四个轮子的目标速度/位置。
- 明确四个电机地址与左前、右前、左后、右后物理轮位的映射，以及每个轮子的方向符号。
- 第一阶段先完成可验证的运动学解算和四轮同步命令组织；定点闭环需使用 OPS 数据作为反馈，并保留失联/超时停止策略。
- 四个电机的同一组运动命令必须使用 X 固件同步参数，全部命令发送完成后再发送同步启动广播。
- 控制路径不得在中断中执行浮点解算或复杂 CAN 发送；中断只置位事件，控制计算和命令发送在主循环或固定周期任务中执行。
- 发送路径应避免四轮控制函数因 FIFO 满而长时间阻塞；具体采用发送队列、增大 FIFO 或分周期发送需在设计阶段确定。
- 新增模块必须遵守 STM32 代码规范，并同步维护对应 `.h/.c` 文件说明。

## Acceptance Criteria

- [ ] 给定明确的底盘几何和方向参数后，能够计算四个轮子的目标速度，直线、横移和原地旋转的符号符合约定。
- [ ] 一组四轮运动指令可在全部电机命令入队后通过一次同步广播启动，控制接口不直接依赖四次调用的时间差。
- [ ] 对零速度、速度限幅、参数非法和 OPS 反馈超时有明确且可验证的行为。
- [ ] Debug 构建成功，且不引入新的编译警告；现有 `main.c` 用户修改未被覆盖。
- [ ] 通过代码检查确认解算、发送、反馈和停止边界清晰，公开接口与实现说明同步。

## Out of Scope

- 不在本任务中修改 OPS 硬件协议或重新设计 X42S 底层 CAN 帧格式。
- 不在没有底盘几何参数和轮位映射前直接写入最终运动学公式。
- 不在本阶段加入视觉识别、路径规划或完整上层任务调度。

## Open Questions

- 需要确认左右/前后中心距的实际数值，以及电机/轮子的减速和细分比例；当前仅确定中心距比例为 `1:1`。
- 需要确认底盘坐标系、OPS 坐标系、正方向和角度单位约定。
